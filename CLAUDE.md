# Break for Cars — BACKEND (game server)

Frontend (3D client) lives at `../Break-for-cars` (see its CLAUDE.md). Colyseus 0.18, hosted on Bloxity Legion.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`; one booted server shared by every test file, `test/server.ts`). Node >= 22. Local multiplayer test: the `break-for-cars-backend` (port 2571) + `break-for-cars-mp` (client with `VITE_SERVER_URL=ws://localhost:2571`) entries in `../.claude/launch.json`.
- The game is client-authoritative and saves in the browser (localStorage); the server relays presence, reports scores and keeps ONE thing per account: the new-player tutorial's step. `src/db.ts` connects to `MONGODB_URI` (injected by Legion; collection `players`, `{ _id: verified uid, tutorialStep, updatedAt }`) before listening; no / unreachable Mongo (local `npm start`, tests) = steps kept in memory (`src/tutorial.ts`). Messages: `tutorialSync` { step } (the client sends it once joined, with its local step) answered with `tutorial` { step } = the further of stored and reported (verified accounts only; guests get no answer and keep it in their browser), and `tutorial` { step } (a new step; saved with `$max`, never lowered). Read once per account per session; `identify` with a new account re-syncs. `TUTORIAL_DONE_STEP` (constants.ts) = the client's `TUTORIAL.steps.length`.
- One room, `world` (`src/rooms/WorldRoom.ts`), reached only through the Bloxity matchmaker (`Legion.SDK.net.resolveEndpoint`, client `net.js`). `ROOM_MAX_CLIENTS = PLOT_COUNT = 6` (`src/constants.ts`): six players, one garage (`plot` 0-5) each. A joining player gets the plot it asks for (`plot` in the join options, the garage it already plays on) when free, else the lowest free one; a dropped connection keeps its seat and garage for `RECONNECT_SECONDS`, a deliberate leave frees it at once.
- Identity (`src/auth.ts`): the client's Bloxity game token is verified with `POST {BLOXITY_API_URL}/v1/auth/game-token/verify` (`{ gameSlug }`, cached by hash); only the returned `user._id` is used (roster `uid`, `signedIn`). No / refused token or an outage = guest (`uid` ""). A `dev-` id from a VITE_DEV_MODE client is accepted only off production. A user id sent by the client is never trusted.
- Roster (`PlayerState`, `src/rooms/schema/WorldState.ts`) and messages (bounded in `src/presence.ts`): `pose` { x, y, z, yaw, speed } (~10/s), `loadout` { tool, toolOut, carry, carryVariant, held } (pickaxe id, block theme + event variant, held car look), `swing` (bumps the `swing` counter), `emote` { id } (sets `emote`, bumps `emoteSeq`), `setAvatar` { avatar } (Bloxity look JSON, opaque, length-capped), `base` { lvl, unl, fl, sk, inc, bays } (the garage, re-serialised: `fl` extra floors bought 0-`FLOORS_MAX`, `sk` garage skin id; up to `BAYS_MAX` bays, 10 per floor; bays are null, blocks `{ k:"b", t, v?, hp, max }` or cars `{ k:"c", t, r, n, l, lv, b, v? }`), `identify` { token, devId, username, pfp } (signed in / out mid-session: re-verified). The join options may carry `pose`, `loadout`, `avatar`, `base` too. Others draw all of it read-only.
- `stats` { cash, income, playtime } (rate-limited, `STATS_EVERY_MS`): queued for Bloxity's boards under the VERIFIED id only (`src/platformBoards.ts`: `POST {BLOXITY_API_URL}/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report` every `PLATFORM_BOARD_EVERY_MS`, `legion_<id>`; the board declarations go with every call and once at boot with no scores, so the boards exist before any signed-in player reports, and `WorldRoom.onDispose` flushes the queue). `PLATFORM_BOARDS` must match the client's `LEADERBOARDS` (config.js).
- `adReward` { rewardToken }: a rewarded ad's token checked once with `POST {BLOXITY_API_URL}/v1/ads/reward/verify` (`src/adReward.ts`); answers `adReward` { ok, reason?: "cooldown" | "invalid" }, at most once per `AD_COOLDOWN_MS` per session. The client's Spin Wheel adds the spin only on ok.
- `src/legion-room-reporter.ts`: this pod's rooms to the matchmaker's cross-pod directory every 2 s (Open Rooms, join by id, friend joins). It and the boards are no-ops without the hosting env (`BLOXITY_REPORT_TOKEN`, `MATCHMAKER_REPORT_URL`, `BLOXITY_GAME_ID`, `BLOXITY_API_URL`).
- `/health` for Legion; `/monitor` and the playground are dev-only. SIGTERM (deploy / scale-down) closes the rooms; clients re-resolve through the matchmaker and rejoin.
- `src/constants.ts` bounds must cover the client's `src/config.js` (catalog ids match `ID_PATTERN`, car names `NAME_PATTERN`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100 for party play; no `seatCap`: the matchmaker sizes pods). Needs repo var/secret `LEGION_GAME_ID` (= `break-for-cars`) and secret `LEGION_DEPLOY_TOKEN`.
